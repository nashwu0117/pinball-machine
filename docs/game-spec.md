# B.B.MAN 夜市彈珠台 — 可執行規格文件

本文件把 [`night-market-pinball-research.md`](./night-market-pinball-research.md) 的研究
結論轉換成可直接對照實作／README 使用的規格。凡標註「〔實機〕」代表有研究來源
（S1–S8，見研究筆記）支持；標註「〔設計〕」代表沒有實機依據、是本專案為了瀏覽器
遊戲可玩性自行設計的決策。每一節與 `src/config.js` 現有常數對照，若規格與現有程式
碼不一致，以現有程式碼行為為準，本文件視為調整時的依據與檢查清單；本次交付若調整
規則文案，會同步更新本文件與 README。

## 1. 定位

- 主題：B.B.MAN／彈珠超人類型的現代投幣式夜市彈珠台〔實機：S1〕，而非 1960 年代
  木製手撥彈珠台（後者已式微，見研究筆記 §2.1 類型 A vs B）〔實機：S7〕。
- 呈現形式：3D 網頁重建，可離線單檔執行（`game.html`），對應真實桌上型機殼比例。

## 3. 遊戲流程

實機官方流程〔實機 S1〕：
```
投幣換取彈珠 → 投入彈珠 → 玩主遊戲 → 遊戲結束 → 取走彈珠 / 繼續遊戲
玩主遊戲細節：紅燈隨機跳動 → 按開始鍵鎖定目標燈號(2/4/6/8/10) → 拉桿發射 → 命中目標燈號球道則獲得對應顆數彈珠
```

對應的狀態機（`src/game.js` 現況，供 README 沿用）：

| 狀態 | 對應實機階段 | 說明 |
|---|---|---|
| `READY` | 投幣前 / 選擇基礎分數與批量模式 | 〔設計〕基礎分數/批量選單是分數制的附加設定，實機無此步驟 |
| `SPINNING` | 紅燈隨機跳動 | 〔實機 S1〕 |
| `AIMING` | 按鍵鎖定目標燈號後、發射前蓄力瞄準 | 〔實機 S1〕鎖定動作 + 〔設計〕拉桿蓄力視覺化為滑桿/長按 |
| `IN_PLAY` | 彈珠在球盤上運行 | 〔設計〕真實剛體物理，非預錄路徑 |
| `RESOLVING` | 彈珠進洞結算 | 〔實機 S1〕命中目標球道判定 + 〔設計〕分數制疊加 |
| `GAME_OVER` | 彈珠用完 (`BALLS = 0`) | 〔實機 S1〕彈珠用完則遊戲結束 |

流程規則細節：
- 一局起始 10 顆彈珠、一次投入一顆〔實機 S1：「投入 10 元可購得彈珠 10 顆」〕。
- 紅燈隨機跳動期間玩家按開始鍵/`SPACE`/點擊跳燈鈕即鎖定目標〔實機 S1〕。
- 鎖定後操作拉桿（滑鼠拖曳、觸控滑桿或 `SPACE` 長按蓄力）發射彈珠〔實機 S1 + 設計〕。
- 短拉未過發射道時彈珠應滾回待發位置、不扣球數〔設計，避免無效操作誤扣資源〕。

## 4. 計分／獎勵規則

**必須在 README 與程式內註解中明確區分以下兩層規則**，避免未來維護者誤以為分數制是實機規格。本節與 `night-market-pinball-research.md` §3 的「設計決策對照表」應保持一致。

### 4.1 實機規則〔實機 S1，一手依據〕
- 命中「本局亮紅燈的指定球道」→ 獲得該燈號對應顆數的彈珠（2/4/6/8/10 選一）。
- 命中其餘球道 → 不退珠，不扣分（實機無分數概念）。
- 官方文件明確排除積分／押分／退幣功能（S1 第 4 條：「無積分、押分、退幣等功能」）。
- 實機贏得的是「更多彈珠」，單位是「彈珠顆數」，非分數或現金。

### 4.2 本專案分數制〔設計，為瀏覽器遊戲可玩性新增〕
- 玩家可選基礎分數 `BASE_SCORE_OPTIONS = [10, 20, 50, 100]`。
- 彈珠落入 9 個倍率洞之一，得分 = `基礎分數 × 洞口倍率`，倍率序列
  `[1, 2, 3, 5, 10, 5, 3, 2, 1]`（左右對稱、中央最高）。
- 批量模式 `SHOT_BATCH_OPTIONS = [5, 10, 20]` 讓玩家一次投入多顆彈珠連續遊玩。
- 統計項目：總分、最高單次得分、各倍率命中次數、最近進洞歷史（供 HUD 顯示）。
- **此分數制是本專案專為瀏覽器遊戲設計的可比較性機制，非實機規格**。官方文件明確排除積功能（S1 第 4 條：「無積分、押分、退幣等功能」），此為「遊戲設計抽象」。
- 實機與本專案規則的對應關係：
  - LED 目標球道（2/4/6/8/10 顆獎勵）→ 實機機制，對應瀏覽器版「是否命中加碼/獎勵」
  - 9 洞倍率洞（1/2/3/5/10/5/3/2/1）→ 專案設計機制，決定「這次命中值多少分」
  - 兩者疊加是本專案獨有的遊戲設計，靈感來自實機機制但非直接重製
- 為避免混淆，請將下列敘述置於 README「實機研究依據」章節旁的「遊戲設計抽象」小節：
  > 「本專案使用『基礎分數 × 洞口倍率』的分數制，是為了讓瀏覽器遊戲擁有可比較的『總分／最高分』目標。實機無分數概念，贏得的是彈珠顆數。」

### 4.3 實機與專案規則對照表

| 實機規則 (S1) | 本專案規則 | 備註 |
|---|---|---|
| 投入 10 元得 10 顆彈珠 | 一局 10 顆、一次投入一顆 | 直接對應 |
| 紅燈隨機跳動 → 按鍵鎖定 2/4/6/8/10 目標 | 紅燈隨機跳動 → 按鍵/SPACE 鎖定 2/4/6/8/10 目標 | 直接對應 |
| 鎖定目標球道 → 獲得對應顆數彈珠 (2/4/6/8/10) | 鎖定目標球道 → 9 洞倍率決定得分 + LED 目標決定是否獎勵 | 設計抽象：實機給球，專案給分 |
| 遊戲結束 → 取走彈珠 / 繼續遊戲 | 球數歸零 → RESOLVING → GAME_OVER | 流程直接對應 |
| 無積分、無押分、無退幣 | 存在「總分／最高分」統計 | 注：總分為設計抽象，非實機規則 |

## 5. 操作提示（UI 文案基準）

沿用專案既有中文提示語氣（口語、簡短、動詞在前），供 HUD/README 對照：

| 情境 | 建議文案 | 觸發時機 |
|---|---|---|
| 開局/待機 | 「按 SPACE 或點白色按鈕開始跳燈」 | `READY` |
| 跳燈中 | 「再按一次鎖定目標球道」 | `SPINNING` |
| 瞄準中 | 「長按 SPACE 蓄力，放開發射；或拖曳拉桿」 | `AIMING` |
| 手機瞄準中 | 「調整下方力道條，按『發射鋼珠』」 | `AIMING`（觸控裝置） |
| 命中高倍率 | 「×10！」＋畫面震動反饋 | `RESOLVING`，倍率 ≥ 5 |
| 球數歸零 | 「彈珠用完，按 R 重來」 | `GAME_OVER` |
| 靜音切換 | 圖示 🔊/🔇 + 快捷鍵 `M` | 任何狀態 |

操作總表（供 README「遊玩」章節沿用，已與 `src/controls.js` 現況一致）：
- 桌面：`SPACE` 開始跳燈/長按蓄力發射、`Enter` 快速發射、拖曳空白處旋轉視角、
  滾輪縮放、拖曳拉桿發射、`R` 重來、`M` 靜音。
- 行動裝置：底部力道滑桿 + 「發射鋼珠」按鈕、直向畫面可完整遊玩。

## 6. 響應式需求

| 斷點 | 需求 |
|---|---|
| 桌面（≥ 1024px 寬，滑鼠/鍵盤） | 顯示完整 3D 自由環繞相機控制、拉桿可直接拖曳、鍵盤快捷鍵全開 |
| 平板/手機直向 | 隱藏滑鼠環繞提示，改為固定/引導式相機角度，確保球盤與控制箱同時可見；力道改用底部滑桿 + 大型發射按鈕（觸控熱區 ≥ 44×44px） |
| 手機橫向 | 允許但非主要優化方向；沿用桌面相機邏輯，力道條移至畫面側邊避免遮擋球盤 |
| 視窗縮放/DPI | Canvas 依 `devicePixelRatio` 重新渲染，HUD 文字與按鈕用相對單位，避免小螢幕文字溢出 |

〔設計〕以上斷點與熱區尺寸為前端通用可用性慣例，非實機考證內容；實機本身是固定
尺寸的實體機台，無響應式概念，此節純為網頁化衍生需求。

## 7. 無障礙需求

現況（`src/ui.js`／`src/controls.js`）已在 `#hud-status` 提供 `aria-live="polite"`，
但完整的焦點導覽與減少動態效果仍列為**待補齊的目標**：

- **色彩對比**：LED 目標燈號、倍率洞顏色須同時搭配非色彩線索（數字/圖示），避免
  色盲玩家無法分辨 2/4/6/8/10 目標球道或倍率洞。
- **鍵盤可操作性**：`SPACE`（蓄力/確認）、`Enter`（快速發射）、`R`（重來）、`M`
  （靜音）已存在；需補上 `Tab` 焦點順序與可見 focus outline，讓純鍵盤玩家能操作
  基礎分數/批量選單與拉桿等價功能。
- **狀態播報**：已以 `aria-live="polite"` 區域播報中文即時狀態；後續仍可為目標燈號與彈珠數補更細緻的語意。
- **動態效果**：畫面震動（`shake`）與蓄力條動畫需支援 `prefers-reduced-motion`，
  偵測到時降低或關閉震動幅度。
- **字級與觸控熱區**：HUD 文字最小字級與行動裝置按鈕熱區（≥ 44×44px）比照 §6。
- **靜音不等於無回饋**：靜音時仍需保留視覺化的命中/失誤回饋（已有畫面震動與文字
  提示，需確保靜音路徑下這些視覺反饋不被連帶關閉）。

## 8. 音效策略

- 全部音效以 **Web Audio API 程序化合成**（`src/audio.js`），不使用任何外部音檔或
  取樣自實機/版權素材的錄音〔設計，呼應研究筆記 §5 版權聲明〕。
- 音效事件清單（對照遊戲狀態機）：
  - 跳燈中的短促「嗶」聲循環（`SPINNING`）
  - 鎖定目標的確認音（`SPINNING → AIMING`）
  - 蓄力/拉桿拉伸的低頻音（`AIMING`）
  - 發射瞬間的彈射音（`AIMING → IN_PLAY`）
  - 撞釘碰撞音（`IN_PLAY`，依碰撞速度調整音量/音高）
  - 命中球道／倍率洞的獎勵音，倍率 ≥ 5 觸發加強版「win」音效（`RESOLVING`）
  - 球數歸零的結算提示音（`GAME_OVER`）
- 靜音狀態（`audio.muted`）需整段線路直接調整 master gain 到 0（現況已用
  `setTargetAtTime` 做平滑淡出，避免爆音），並在畫面上以圖示狀態呈現（🔊/🔇）。
- 〔設計〕夜市攤位環境音（人聲/叫賣/其他攤位背景噪音）目前不在範圍內；若之後要加
  入，同樣須以程序化合成或自行錄製的原創素材為之，不得使用受版權保護的錄音。
